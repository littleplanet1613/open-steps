# os-check-work — перепроверить работу другой сессии

## Зачем нужен

Этот skill нужен, когда другая сессия, агент или исполнитель говорит: **«готово»**.

Его задача — не пересказать отчёт, а проверить, соответствует ли он реальному состоянию проекта.

Главный принцип: **отчёт — это заявление, а не доказательство**.

## Когда использовать

- предыдущая сессия закончила работу;
- нужно принять работу другого агента;
- нужно проверить PR перед следующим этапом;
- есть фраза «всё готово», но хочется убедиться;
- нужно понять, можно ли уже закрывать задачу.

## Что он проверяет

В зависимости от доступных инструментов skill сверяет:

- фактический diff;
- состояние PR;
- CI/checks;
- approval/review;
- не появились ли лишние изменения вне задачи;
- действительно ли добавлены заявленные тесты;
- не устарела ли ветка;
- что именно осталось непроверенным.

Результат должен разделять:

```text
Заявлено: все проверки прошли.
Фактически: 12 из 12 checks зелёные.
```

или:

```text
Заявлено: задача полностью готова.
Фактически: код готов, но после последней правки CI ещё не запускался.
```

## Главное изменение нашей версии

**Этот skill не делает merge автоматически.**

Если работа прошла проверку, он пишет, что PR готов к merge и рекомендует следующий шаг. Сам merge выполняется только после явной команды пользователя вроде:

```text
Мержи PR.
```

Запросы `проверь`, `готово?`, `можно принимать?` разрешением на merge не являются.

## Если найдена ошибка

Skill не должен молча чинить чужую работу и потом объявлять её принятой. Он обязан:

1. назвать расхождение;
2. показать, что было заявлено и что найдено;
3. подготовить понятную инструкцию для сессии/агента, который должен исправить проблему.

## Хороший запрос

```text
Используй os-check-work. Не верь отчёту прошлой сессии на слово: проверь PR, diff и checks по факту. Ничего не мержи без моей отдельной команды.
```
