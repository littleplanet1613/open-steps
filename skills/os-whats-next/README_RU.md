# os-whats-next — что делать дальше

## Зачем нужен

Этот skill отвечает не списком из двадцати задач, а выбирает **один следующий шаг**, который сейчас даёт больше всего пользы или разблокирует работу.

Он должен смотреть на реальное состояние проекта, а не придумывать задачи из головы.

## Когда использовать

Подходит для запросов:

- «что дальше?»;
- «что осталось?»;
- «за что браться следующим?»;
- «есть что-то, что я должен сделать?»;
- «что сейчас блокирует проект?».

## Что он смотрит

По возможности:

1. последний отчёт предыдущей сессии;
2. локальные изменения;
3. открытые PR;
4. backlog / roadmap / issues.

После этого делит работу на две группы:

- агент может сделать сам;
- без пользователя не обойтись.

И выбирает **одну рекомендуемую следующую задачу**.

## Пример результата

```text
Основная функция готова, но финальная проверка после последней правки ещё не выполнена.

Могу сделать сам: перепроверить текущий PR и проверки.
Нужно от вас: ничего.

Следующее: проверить финальное состояние PR — это единственное, что мешает закрыть задачу.
```

## Главное изменение нашей версии

Оригинальная версия могла автоматически merge готовый PR как «завершение уже законченной работы».

В нашем форке это запрещено.

`os-whats-next` может сказать:

```text
PR проверен и готов к merge. Рекомендую следующим шагом выполнить merge.
```

Но сам merge выполняется только после отдельной явной команды пользователя.

## Чего он не должен делать

- придумывать задачи, которых нет в backlog/состоянии проекта;
- скрывать, что часть источников не была проверена;
- начинать новую большую работу без выбора пользователя, если есть реальная развилка;
- автоматически merge/deploy только потому, что это выглядит логичным следующим шагом.

## Хороший запрос

```text
Используй os-whats-next. Посмотри фактическое состояние проекта и выбери один следующий приоритетный шаг. Не мержи и не деплой ничего без моей отдельной команды.
```
