# os-step-by-step — когда без пользователя не обойтись

## Зачем нужен

Этот skill не должен перекладывать техническую работу на пользователя. Его принцип: **сначала агент сам делает всё, что может безопасно сделать, и только потом просит человека о минимально необходимом действии**.

## Когда использовать

Когда нужно:

- нажать кнопку в интерфейсе;
- подтвердить разрешение;
- войти в аккаунт;
- выполнить действие на личном устройстве;
- ввести секрет напрямую в сервис;
- выбрать вариант;
- проверить то, что агент физически не может увидеть сам.

## Как он работает

Перед тем как просить вас что-то сделать, агент обязан:

1. попробовать сделать это сам;
2. проверить другой доступный путь;
3. сократить вашу часть до минимального шага;
4. убедиться, что уже не просил то же самое раньше.

После этого он даёт **один понятный шаг за раз** и объясняет, как понять, что всё получилось.

## Пример

Плохо:

```text
Настрой GitHub App permissions и проверь installation scope.
```

Хорошо:

```text
Открой GitHub → Settings → Applications → Installed GitHub Apps.
Нажми Configure рядом с ChatGPT.

Как поймёшь, что всё получилось: в списке репозиториев появится нужный проект.
После этого я сам проверю доступ.
```

## Секреты

Пароли, токены, private keys и connection strings не нужно вставлять в чат, если их можно ввести прямо в целевой сервис или безопасно через терминал.

Skill должен объяснить, **куда именно** ввести секрет, но не просить показать его значение агенту.

## Опасные действия

Если шаг касается production, удаления, денег, миграции или другого труднооткатного действия, простой пошаговой инструкции недостаточно.

Сначала:

1. проверка риска через `os-what-could-go-wrong`;
2. понятное описание последствий;
3. явное подтверждение пользователя;
4. только потом сам шаг.

## Хороший запрос

```text
Используй os-step-by-step. Сам сделай всё, что можешь. Мне дай только те действия, которые без меня реально невозможно выполнить, по одному шагу и без технического жаргона.
```
