# os-done-or-not — задача реально закончена или нет

## Зачем нужен

Этот skill включается в конце работы и отвечает на главный вопрос: **можно ли считать задачу законченной**.

Он не должен заваливать пользователя commit SHA, названиями веток и техническим жаргоном. Вместо этого он выдаёт короткий человеческий итог: что получилось, что проверено, что осталось, нужен ли человек и безопасно ли закрывать задачу.

## Когда использовать

Подходит для запросов вроде:

- «готово?»;
- «мы закончили?»;
- «что в итоге сделал агент?»;
- «можно закрывать задачу?»;
- «дай итог работы».

Также его может вызывать stop-hook после того, как агент реально изменил проект.

## Что он делает

1. Смотрит текущее состояние работы.
2. Отделяет подтверждённое от непроверенного.
3. Даёт короткий отчёт с понятным verdict.
4. Сохраняет техническую часть отчёта для следующей сессии.

Типовой результат:

```text
Функция добавлена и работает в проверенном сценарии.

✅ Основная задача выполнена
⚠️ Один сценарий после последней правки не перепроверен

Полностью готово? Нет
Что нужно от вас? Ничего
Можно закрывать? Пока нет — нужна финальная проверка
```

## Правило нашей версии

Для важных изменений старый отчёт или тест из предыдущей сессии не считается свежим доказательством.

Если после финальной правки нужная проверка не выполнялась, skill обязан сказать **«не проверено»**, а не ставить уверенное `Да`.

## Чего он не делает

- не делает merge автоматически;
- не запускает production deploy;
- не скрывает плохие новости ради красивого финального отчёта;
- не превращает предположение в факт.

## Хороший запрос

```text
Используй os-done-or-not. Скажи простыми словами, задача реально закончена или ещё что-то осталось. Не считай старые проверки актуальными, если после них менялся код.
```
