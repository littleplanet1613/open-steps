# os-say-simple — перевести сложный текст на человеческий язык

## Зачем нужен

Этот skill берёт уже существующий технический текст и переписывает его проще, **не меняя факты**.

Он особенно полезен для:

- отчётов агентов;
- сообщений об ошибках;
- review comments;
- CI/deploy логов;
- длинных технических объяснений;
- собственного ответа агента, если он получился слишком сложным.

## Когда использовать

По запросам вроде:

- «объясни проще»;
- «что это значит?»;
- «короче»;
- «я не понял»;
- «переведи на человеческий».

Если вопрос не про смысл текста, а про то, **что конкретно делать дальше**, нужен `os-step-by-step`.

## Главный принцип

Skill меняет только форму, а не содержание.

Он обязан сохранить:

- все числа;
- даты;
- предупреждения;
- риски;
- оговорки;
- точные команды и код.

Если исходный текст говорит «проверки вроде прошли», нельзя переписать это как «всё проверено».

## Пример

Было:

```text
CI pipeline failed on the deploy job because the production token was not available in the environment scope.
```

Стало:

```text
Публикация не запустилась, потому что у этого шага не было доступа к production-токену. Код может быть исправен — проблема сейчас в доступе к секрету.
```

## Если пользователь просит конкретное число пунктов

Например:

```text
Объясни это в 3 пунктах.
```

Skill должен дать ровно три реальных пункта, если в исходнике их действительно столько. Он не должен выдумывать «третий пункт» ради красивого количества.

## Правило нашей версии

Упрощение не должно скрывать риск. Если исходник содержит предупреждение про потерю данных, production или необратимость, оно остаётся явным и заметным.

Если требуется узнать, **правда ли написанное в отчёте**, а не просто понять его, используется `os-check-work`.

## Хороший запрос

```text
Используй os-say-simple. Объясни этот отчёт без технического жаргона, но не теряй ни одного числа, предупреждения или ограничения.
```
