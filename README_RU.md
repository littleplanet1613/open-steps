# Open Steps — русская инструкция

Это форк `kharmanskyi/open-steps`, адаптированный для понятной работы с Codex/Claude Code и для пользователя, который не обязан разбираться в коде.

Главная идея: агент не просто пишет код, а объясняет, **что он сделал, что проверил, что осталось и что нужно от человека**.

## Что изменено в этом форке

- добавлены русские описания и инструкции к каждому из 7 skills;
- добавлены правила безопасной работы;
- `merge` больше не выполняется автоматически только потому, что работа кажется готовой;
- `deploy`, удаление данных/ресурсов, миграции, платежи и другие труднооткатные действия требуют явного разрешения пользователя;
- важный результат нельзя объявлять проверенным по старому или чужому отчёту: состояние нужно перепроверять по факту;
- технические отчёты переводятся в понятный человеческий итог.

## 7 skills

| Skill | Что делает | Когда полезен |
|---|---|---|
| [`os-done-or-not`](skills/os-done-or-not/README_RU.md) | Проверяет, действительно ли работа закончена, и даёт понятный итог | В конце задачи, после кодинга, перед закрытием работы |
| [`os-step-by-step`](skills/os-step-by-step/README_RU.md) | Сначала пытается сделать всё сам, затем даёт человеку только необходимые шаги | Когда нужно что-то нажать, подтвердить, ввести или проверить на устройстве |
| [`os-check-work`](skills/os-check-work/README_RU.md) | Не верит отчёту другой сессии на слово и сверяет его с реальным состоянием | При передаче работы между агентами/сессиями, перед принятием PR |
| [`os-what-could-go-wrong`](skills/os-what-could-go-wrong/README_RU.md) | Делает премортем: ищет, что может сломаться до труднообратимого решения | Перед запуском, миграцией, крупным изменением, покупкой или другим риском |
| [`os-whats-next`](skills/os-whats-next/README_RU.md) | Выбирает один следующий приоритетный шаг на основе реального состояния проекта | Когда спрашиваете «что дальше?» или «что осталось?» |
| [`os-ask-simple`](skills/os-ask-simple/README_RU.md) | Переводит технический выбор в простой вопрос и даёт рекомендацию | Когда агенту нужно спросить вас о техническом решении или предложить варианты |
| [`os-say-simple`](skills/os-say-simple/README_RU.md) | Переписывает сложный технический текст простыми словами без потери фактов | Когда отчёт, ошибка или объяснение непонятны |

## Наши правила безопасности

Полная версия: [`docs/SAFETY-RU.md`](docs/SAFETY-RU.md).

Коротко:

1. **Никакого автоматического merge.** Агент может проверить и рекомендовать merge, но выполняет его только после явной команды пользователя.
2. **Никакого автоматического deploy/production release.** Сначала проверка, затем понятное объяснение, затем разрешение.
3. **Удаление, миграции, платежи и другие труднообратимые действия** — только после явного подтверждения.
4. **Чужой или предыдущий отчёт — это заявление, а не доказательство.** Перед важным действием состояние перечитывается заново.
5. **Если проверка не была выполнена после финальных изменений — результат называется `не проверено`, а не `готово`.**

## Установка в Codex

Skills используют общий формат `SKILL.md`. Для Codex их можно установить в `~/.agents/skills/`.

Из папки, в которой находится клонированный репозиторий:

```bash
mkdir -p ~/.agents/skills && cp -R open-steps/skills/os-* ~/.agents/skills/
```

Чтобы Codex автоматически выбирал нужный skill в нужный момент, добавьте routing block в глобальный `AGENTS.md`:

```bash
mkdir -p ~/.codex && grep -q 'os-done-or-not' ~/.codex/AGENTS.md 2>/dev/null || cat open-steps/docs/routing-block.md >> ~/.codex/AGENTS.md
```

После обновления репозитория (`git pull`) повторно скопируйте skills, чтобы локальная версия обновилась.

### Hooks в Codex — опционально

Hooks позволяют автоматически передавать следующей сессии итог предыдущей работы и требовать финальный отчёт после реальных изменений.

В `~/.codex/config.toml` указываются абсолютные пути к:

- `hooks/session-start.sh`
- `hooks/stop-report.sh`

При первом запуске Codex попросит доверить hooks. Не подтверждайте незнакомые hooks вслепую — сначала проверьте их содержимое.

## Как пользоваться

Обычно вручную вызывать skill не нужно: routing block должен подбирать его сам.

Но можно обращаться явно:

```text
Используй os-check-work и перепроверь работу прошлой сессии.
```

```text
Используй os-done-or-not и скажи человеческим языком, задача реально закончена или нет.
```

```text
Перед деплоем используй os-what-could-go-wrong и покажи, что может сломаться.
```

## Рекомендуемый рабочий порядок

`задача → работа агента → проверка → понятный итог → решение пользователя → только потом труднообратимое действие`

То есть skill-пак не должен превращать агента в полностью автономного администратора. Его задача — сделать агента **понятным, проверяемым и предсказуемым**.
